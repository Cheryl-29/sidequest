# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make install        # venv + pip install -e '.[dev]' + npm install --prefix frontend
make places-demo    # offline 157-place index from the committed probe; skips an existing index
make test           # ruff check backend && pytest -q && npm run build --prefix frontend
make eval           # frozen acceptance scenarios -> reports/latest-eval.json (exits non-zero on any failure)
make dimensions     # taste-dimension gates vs the candidate pool -> reports/latest-dimensions.json
make run            # build frontend, then uvicorn with --reload on :8000
```

Single test / subset:

```bash
.venv/bin/pytest backend/tests/test_planner.py::test_missing_hours_are_unknown_not_verified -q
```

Drive the agent from the terminal (real model calls; needs `OPENAI_API_KEY` in `.env`, with optional `OPENAI_MODEL` / `OPENAI_BASE_URL`):

```bash
PYTHONPATH=backend .venv/bin/python scripts/run_agent.py --say "下午空出来了" --hours 3 --reroll too_obvious
```

Frontend-only dev loop (Vite on :5173 proxies `/api` to :8000):

```bash
npm run dev --prefix frontend
```

`PYTHONPATH=backend` is required for `uvicorn` and anything under `scripts/`; pytest gets it from `pyproject.toml`. CI (`.github/workflows/ci.yml`) runs exactly the `make test` steps plus `run_eval.py` and `check_dimensions.py`, so run all three before claiming a change is done.

Simulated users and search recall (M5′, no network, no model):

```bash
PYTHONPATH=backend .venv/bin/python scripts/build_places.py data/probes/20260914T041841Z/{harbour,glebe,surry_hills}.response --timestamp 2026-09-14T04:18:41Z --out /tmp/probe.sqlite
PYTHONPATH=backend .venv/bin/python scripts/run_personas.py --places /tmp/probe.sqlite   # -> reports/latest-personas.json
PYTHONPATH=backend .venv/bin/python scripts/check_reference.py                          # -> reports/latest-reference.json
```

`run_personas.py` excludes holdout personas unless `--holdout` is passed; only pass it for a frozen configuration.

Place index: `scripts/fetch_places.py` makes one real Overpass request (batch job, run by hand, never in tests) and `scripts/build_places.py <json…>` builds the SQLite index at `data/places/sydney.sqlite` (git-ignored; override with `SIDEQUEST_PLACES_DB`). `build_places.py` also accepts the M0 probe responses for an offline small index. `check_dimensions.py --places <sqlite>` gates an index and writes `reports/latest-dimensions-osm.json` without touching the CI report. Dimension status can depend on the pool (D2 is `pending` on the fixed pool, `active` on OSM pools), coverage only counts candidates a dimension applies to (D3 skips errands), and D3 is a reserved research dimension since v2.3 whose `obviousness` comes only from the OSM tag formula (the Wikidata sitelinks enrichment and human labels were removed in v2.4). `run_personas.py` blocks personas on whatever dimensions the given index actually passes.

`data/probes/20260914T041841Z/` is the only M0 probe snapshot kept (the harness tests and the offline index use it); the M0 probe scripts, TfNSW/DDGS snapshots and `evals/provider-m0.json` were removed in v2.4.

## Architecture

A FastAPI backend (`backend/sidequest/`, twelve modules) plus a single-file React SPA (`frontend/src/main.tsx`). The backend serves `frontend/dist` at `/` when it has been built.

**Request flow:** `POST /api/runs` validates a `Request`, persists a `queued` document, and launches an asyncio task; the browser follows `GET /api/runs/{id}/events` (SSE, polls the DB every 100 ms) for status, trace steps and the final result. Planning itself is synchronous and runs in `asyncio.to_thread` with a 60 s timeout.

**Two independent status axes — do not conflate them.** A *run* is `queued → running → completed | search_exhausted | needs_input | failed | cancelled | interrupted`. An *itinerary* is `verified | conditional | infeasible`. `search_exhausted` means the tool budget or candidate set ran out, never that no solution exists.

**Provider boundary:** `planner.plan()` consumes the `PlannerTools` protocol (`retrieve`, `route`, `log`, call budget, revision cache). `ReplayTools` (in `planner.py`) serves synthetic fixtures; `LiveTools` (in `providers.py`) serves an M0-verified CBD venue allowlist plus `TfNSWRouteProvider`. `Request.mode` (`replay` | `live`) selects the route source; `Request.catalog` (`fixed` | `osm`) independently selects the candidate source, and `planner.catalog()` is the single switch both the planner tools and the agent go through (the agent locks an id the planner must retrieve again). Any new data source implements this protocol rather than being called from the planner directly.

**Validation is the core of the product.** `planner.validate()` runs the full chain — outbound, inter-stop and return legs — and each `Check` is `pass | fail | unknown`. Any `fail` ⇒ `infeasible`; any `unknown` ⇒ `conditional`; only an all-`pass` chain is `verified`. Individually open venues can still fail as a chain, and that is intentional test-covered behaviour.

**Evidence:** every fact carries `source_url`, `fetched_at`, `valid_from`, `valid_until` and a `synthetic` flag (`True` for fixtures, `False` for curated venues and TfNSW). Evidence that does not cover the stop or leg window yields `unknown`, never `pass`.

**Storage** (`storage.py`) is one SQLite `documents` table holding JSON, keyed by `(id, owner)`; every read and write is owner-scoped by the session cookie. `Store.change(..., expected=[...])` is a compare-and-swap: it is what stops a cancelled or superseded run from being overwritten by a late result. `Store.recover()` marks abandoned `queued`/`running` rows `interrupted` at startup.

**Taste layer** (`taste.py`). A `Feedback` is one reroll carrying a typed `Reason`. Reasons fall into exactly eight scopes (`SCOPES`) and an import-time assert enforces the partition: `TASTE_REASONS` move one D1/D2 belief, `LOCAL_REASONS` (`too_obvious` / `too_obscure`, plan v2.3) set a one-shot hint (`TasteState.local_obviousness`/`local_kind`/`local_reference`) that re-sorts candidates of the rerolled-away kind by obviousness for the next planning round and is then cleared (`clear_local_reroll`) — it is never an episode signal, belief, proposal or memory item, `KIND_REASONS` penalise a category for the session, `STATED_REASONS` (`never_here`) return an `Outcome.stated` proposal the caller confirms, `CONSTRAINT_REASONS` patch the `Request`, `DEDUP_REASONS` only mark candidates consumed, `ROUTE_REASONS` (`off_route`) reject only the side stops and return `Outcome.keep` so the next round re-bets on the same anchor (the run record's `keep`, passed to `propose_quest(keep=...)` or locked for that round only on the fixed planner — never stored in the request), `SESSION_REASONS` (`other`) keep unmapped free text as session context. `taste.py` owns the evidence rules (`reroll_signals`, `accept_signals`): which reroll or accept supports or contradicts which memory item; reasons outside those functions are evidence for nothing. Three rules are load-bearing and easy to erode: `been_there` expresses no taste (the user may have gone because they liked it), and `too_far` stays qualitative — it must never be turned into a `max_walk_minutes`, and a complaint about a side stop ("咖啡店离海滩太远") is `off_route`, never `too_far` — `interpret_feedback` is given each stop's role and distances for exactly this. `Belief` is an observation count, deliberately not a calibrated probability. `TasteState.rejected` accumulates every rerolled-away candidate for the session and the agent hard-skips them; never overwrite it per reroll — a round with no quest sends no ids and would wipe the memory.

**Memory** (`memory.py`, plan v2.2 §7.4). Dimensions are the probe action space and persona axes only; long-term memory is typed `MemoryItem`s (`dimension`, `category`, `place`, `note`), each optionally scoped to a `Context` (slot × span) computed from the request clock — never asked, never named by the model. Every reroll/accept becomes an `Episode` with its context and signals; `Memory` only counts them. Invariants: only `confirm()` creates an active item (`apply()` never does); a proposal needs `PROPOSE_SUPPORT` in one context across ≥`PROPOSE_SESSIONS` sessions with no contradiction there; evidence is tallied per context, so a contradiction in another context is not a contradiction; a global item needs every context with evidence for the key to be contradiction-free, and then either ≥2 contexts each ready on their own, or pooled support ≥`PROPOSE_SUPPORT` across ≥`PROPOSE_SESSIONS` sessions with a reroll in ≥2 contexts (accepts alone never pool: they mostly echo the ranker's defaults, e.g. a short window leaning near); a context item beats a global one on the same key in `recall()`; repeated contradiction yields a narrow/retire *proposal*, never an automatic change; `forget()` is immediate and blocks re-proposal, `forget_episode()` unconfirms agent-proposed items that drop below threshold but never user-stated ones. In scoring, `note` items never score or filter, `place/never` is a hard skip, and all memory adjustments are capped at `MEMORY_CAP` (one dimension hit) so memory cannot overrule what the user says now. `agent.targets` order: session feedback > explicitly said intent > recalled items > inferred intent. Only `taste.LEARNED_DIMENSIONS` (D1, D2) become memory; `TasteState.recall()` and `proposals()` filter out any D3 dimension item or proposal left in an older database. Memory persists as one owner-scoped document (`memory.load/save`).

**Place discovery** (`places.py`, plan v2.1 §5). Retrieval is centred on the request origin with a radius derived from the free window, capped per kind per half-radius ring so D2 keeps both poles. OSM facts stay out of the verdict: `opening_hours` never becomes `open_at`/`close_at` and `fee` never becomes `cost`; the hours tag is used only to drop places a *fully parsed* tag shows shut for the whole window — anything unparseable (PH, sunrise, overnight) is kept. `Candidate.obviousness` (research-only D3, used by the local reroll hint) comes from the place's own tags (Wikipedia/Wikidata/attraction), never from user history. Errand kinds (supermarket, bakery, cafe…) carry an `action` hint for narration and `obviousness=None` — D3 says nothing about them. Kinds whose default stay alone fills the window are dropped at retrieval.

**Agent layer** (`llm.py` + `agent.py`; driven by `scripts/run_agent.py` and by the API with `POST /api/runs?strategy=agent`). `llm.py` is the only file that knows the provider: `OpenAIModel` talks JSON-schema structured output over `httpx` (no SDK dependency), with typed errors mirroring `providers.py` and a decision budget. `agent.py` runs one round: `infer_intent` (whose `Intent.places` holds only kinds the user named, e.g. 海边 → beach) → `choose_probe` → (OSM catalog only) `search_places`, which picks kinds from a fixed enum and never empties the round → deterministic `targets()`/`score()` against the production dimensions (D1, D2) → the winner goes to `plan()` as a **locked stop** → `narrate()`. The model decides WHERE; the executor decides IF and HOW, so a bad reply yields a dull quest, never an unreachable one. Narration citations are checked against real evidence ids (invented ids are dropped) — that validates the citation, not the claim. The hook's "why now" comes from `moment.py`, not encyclopedia text: computed facts with citable ids — sunset relative to the stops (`clock:sunset:<date>`; when, never whether there is anything to see), the free window (`clock:window`), each leg (its evidence id), and only those ranking memory items the anchor agrees with (no dislikes, no notes). Place-specific current content (exhibitions) is the planned RAG entry point, plan §7.1; none of it ever feeds the verdict. Ranking ends in a seeded weighted draw (`agent.draw`) among the top 5 that score strictly within one axis hit (3.0) of the best, so variety never trades away a dimension match; the seed is logged and returned as `AgentResult.seed`, and tests/evals pass a fixed one. Randomness belongs here, not in model temperature. Named kinds are drawn before everything else and are added back if the search filter dropped them, except kinds rejected this session and candidates that miss a dimension the user settled this session (session feedback still outranks what was said). Every attempt passes the session's rejected ids as `excluded_ids`, so a rerolled-away place cannot return as a neighbouring stop. `Quest.anchor_id` records what the agent bet on, since `plan()` may reorder stops. Candidates whose known hours rule out the whole window are dropped before planning (equivalent to the opening_hours check, not a guess); if nothing is left the round returns without spending a model call and `explain_empty()` says what emptied it.

**Taste API** (`api.py`). One taste session per quest thread: `POST /api/runs` starts a fresh `TasteState` (memory and the incognito flag carry over; an idempotent retry does not reset it), rerolls and revisions continue it; the session lives in document `taste:{owner}`, memory in `memory:{owner}`. `POST /api/runs/{id}/reroll` applies a typed reason, confirms a `never_here` statement, excludes everything rerolled away or banned (a lock still wins), and re-plans; `bad_time` returns `clarify` without launching. `POST /api/runs/{id}/accept` records the "就这个" episode. After planning, `agent.rank_itineraries` reorders the fixed planner's feasible itineraries by the same `targets`/`score`/memory adjustment the agent uses — no model call, planner order breaks ties — and appends `taste_miss` to the trace when nothing feasible matches the aim (feasibility outranks fit; the UI shows it). Proposals are recomputed server-side and answered by `signature` (`POST /api/taste/proposals`), so a client can never author one; at most one unprompted proposal is offered per session. `GET /api/taste`, `POST /api/taste/notes`, `DELETE /api/taste/items|episodes/{id}` and `PUT /api/taste/settings` back the preferences drawer; the old free-text `/api/memories` is gone.

**Agent over the API.** `strategy` (`fixed` default, `agent` only when `llm.openai_configured()`; tests inject `create_app(model_factory=...)`) is stored on the run and inherited by rerolls; revisions always use the fixed planner because the agent overwrites `locked_ids`. Agent steps stream over SSE as they happen (`on_step` writes `progress` with a compare-and-swap on `running`; a cancelled or timed-out round raises `AgentAborted` at its next step so an abandoned thread never writes). Any `ModelError`, a timeout (`AGENT_TIMEOUT`), or a round where every bet failed validation after spending model calls degrades to the fixed planner with a `degrade` trace step the UI shows; a round that returned nothing without calling the model is left alone. Agent results use the normal `Result` shape (`title`=brief, `reason`=hook, `strategy="agent-v1"`) plus `result.agent` (anchor, memory ids, probe, intent, seed, calls, tokens). Rerolls reuse the parent intent. The model's `search_places` kind filter is a hint: its prompt carries what the user said this session or confirmed for this context (`agent.stated`), and `keep_what_the_user_asked_for` restores nearby candidates when the filter removed every one that fits those preferences (seen with gpt-4o-mini: errand kinds only at lunch, five "想动一动" rerolls, five bubble-tea shops). `agent.targets` also aims D2, but only from session feedback or memory (never from the opener); with neither, a free window ≤ `NEAR_BY_DEFAULT_MINUTES` leans near as the weakest source (plan v2 §1.1 corollary 2). `agent.probeable` offers D1 while the session has not settled it, and D2 (`near` / `farther`, plan v2.3) only when the window exceeds `NEAR_BY_DEFAULT_MINUTES` and neither session nor memory has D2 evidence; a probe only reorders candidates that already passed hard constraints and never derives or patches `max_walk_minutes`. After a `too_obvious`/`too_obscure` reroll, `search_places` keeps the rerolled kind in the pool for that one round so the local hint can act. `reason="other"` + `note` goes through `agent.interpret_feedback`, which may map onto any typed reason except `never_here` (a permanent ban needs the explicit chip); unmapped text becomes `TasteState.session_notes`, is re-read by `infer_intent` for the rest of the session, and only unmapped text may yield a note proposal (`TasteState.pending`) — mapped text already counts toward a typed item and must earn its proposal across sessions. `agent.strip_user_claims` drops narration sentences that say what the user said or likes when no confirmed memory backs the round.

**Evaluation harness** (`personas.py`, `harness.py`, `reference.py`; plan v2.2 §8). Personas in `evals/personas.json` are synthetic, fully structured and hidden from the agent — the harness passes only typed feedback, accepts and proposal answers, and `Persona.judge` is deterministic with a fixed order of concerns (never → disliked kind → D1 → D2); personas stratify on D1/D2 only. Personas requiring an inactive dimension are reported as blocked, not run. Six groups share one loop; ablations (`flat_profile`, `typed_no_context`, `no_memory`, `last_feedback`) are applied by rewriting what the group may store, never by changing product code, so `typed_context` is what ships. `RuleModel` stands in for the LLM (seeded probe lean, exploits dimensions the prompt already reports observations for); its numbers describe the memory and ranking machinery, not model judgement. Reports carry raw numerators/denominators; do not tune on holdout personas. Out-of-context misuse only counts first rounds that recalled memory actually shaped. `reference.enumerate_feasible` tries every ordered combination through the same validator (replay only) to measure the fixed planner's search recall; it cannot catch validator bugs.

**Revisions** (`POST /api/runs/{id}/revise`) merge a partial `Revision` over the parent request, re-validate, and pass the parent's route cache into the new run.

## Invariants worth preserving

These are deliberate and covered by tests in `backend/tests/` and `evals/scenarios.json`:

- Missing facts stay missing. Never substitute a default for absent opening hours, cost or event times — under the default `Request.venue_facts="verdict"` the result must degrade to `conditional`. Under `"advisory"` (the agent path, plan v2.1 §6.1) missing hours and uncovered venue evidence are still `unknown` checks — never `pass` — flagged `Check.advisory` and listed in `Itinerary.advisories` instead of lowering the verdict; a *known* closing time still fails. Do not extend advisory to other checks without updating §6.1.
- Route cache keys include the exact departure instant, plus the adapter version and ceil-to-minute departure (live). Never key a leg by endpoints alone.
- Unknown fare is not zero fare. Budget covers tickets and activities; transport joins only when `include_transport_cost` is set, and a missing Opal fare must not downgrade an otherwise verified plan on its own.
- A user-locked stop is never silently replaced; a closed lock returns `needs_input`.
- User input never forms a URL. The TfNSW and Open-Meteo endpoints are fixed constants; `preference` text is inert data (there is an explicit prompt-injection test).
- `TFNSW_API_KEY` and `OPENAI_API_KEY` live only in the git-ignored `.env`, is read via `providers.load_local_env`, and go into the `Authorization` header — never into query params, logs, caches, probe reports or `/api/health`.
- All datetimes are timezone-aware and normalised to `Australia/Sydney` (`models.SYDNEY`); `Request` rejects naive times, DST-imaginary wall times, cross-midnight windows, and windows outside 30 min – `models.MAX_WINDOW_MINUTES` (4 h, plan v2.5: a full day is a trip, not a side quest).
- Coordinates are clamped to the Sydney bounding box by the `Request` field constraints.

## Conventions

- User-facing strings — HTTP error details, trace summaries, itinerary copy, `README.md` — are Chinese. Code, comments and `docs/` are English. Match whichever surface you are editing.
- The planner is an explicit fixed policy (`fixed-v1`), not an LLM: ranking, a ≤6-combination search and permutation ordering by coarse haversine distance. Coarse distance only chooses an order; feasibility always comes from provider legs. Around a locked stop, added stops must be within `planner.SIDE_KM` of a lock and of a different category (seen live: a corner shop and a cafe at home around a beach 4 km away); if none qualify the quest is the lock alone.
- `evals/scenarios.json` holds 24 frozen dev/holdout cases (16 dev, 8 holdout), and `scripts/run_eval.py` asserts observable outcomes independently of the validator's own verdict — keep expectations outside validator internals when adding cases.
- `docs/architecture.md` covers lifecycle, evidence and caching semantics; `docs/data-feasibility.md` records what M0 verified and what is explicitly out of first-release Live scope (timed events, unverified parks). `Sidequest_项目计划_v2.md` is the current plan (v1 was removed in v2.4): the product is an inspiration/side-quest generator, not an itinerary comparison tool. Its v2.1 revision makes live place discovery around the user's origin the target; the curated venue allowlist is a temporary Live strategy and a Replay baseline, not the product's candidate source — M3′-0 manual verification is no longer the main path. M0–M2 (deterministic core, evidence, validator, replay, frozen-scenario eval) are done and stay as the foundation; the remaining work is the taste/feedback loop, the agent decision layer, and a simulated-user convergence eval. Ranking is feasibility × fit only — there is deliberately no novelty objective. Production taste dimensions (plan §4.3, v2.3) are D1 form and D2 travel-willingness. D3 obviousness was retired as a global preference in v2.3 ("likes niche" rarely generalises beyond one category, and the OSM pool's minority side was only 10.9%): it is `reserved` in `check_dimensions.py`, never enters `choose_probe`, global targets, episode signals, long-term memory or persona stratification, and survives only as the research field `Candidate.obviousness`, the local one-shot reroll hint, Do not revive it as a global dimension by tuning thresholds or adding popularity sources. D3 remains a property of the candidate itself (is it the obvious tourist answer?), never a distance from the user's own history. Its three tiers (`taste.D3_TIERS`: 冷门 / 有点名气 / 大众答案) and the helpers `aim_value` / `fit` / `pole_of` are kept for the research report; the gate binarises D3 at its best cut. D4 mood is reserved until fully annotated.
